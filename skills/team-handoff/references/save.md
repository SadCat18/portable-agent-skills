# 保存：全组交接 / 本角色交接 / 更新进度

## A. 全组交接：由已登记的协调者执行

1. 核对用户指派、TEAM.md 角色列表、工作目录、文件访问与通信能力。
   读取适用项目规则和实际现场，不假称已联系角色。
2. 续用未完成保存批次或建立唯一批次，记录带时区的可用真实时间；无法取得时写未知。
   使用 team/current/index/tasks 模板，标 preparing_batch 和 PAUSED，保留 latest_sealed_batch。
   暂停新派单，在途操作到安全检查点，不停止正常线上服务。
3. 向每个登记的执行角色请求本角色交接，消息带项目、批次、目标文件、写入范围与回执入口。
   只在用户授权且工具可用时通信；否则生成逐角色人工转发提示词并标 WAITING。
   对方没有安装 skill 时提供本文件 B 节及角色模板必要字段，不强制先安装。
4. 协调者按 role 模板保存自身状态与任务看板，也提供真实 HANDOFF_ACK。
   仅确有运维职责时追加 server-extra；远程核实须在已有授权范围内。
5. 核对所有登记角色材料、真实回执、安全停靠、后台作业方案、任务/接口一致性、代码改动、共享可读性与脱敏。
   缺少旧会话只能报告部分交接或经用户认可的有限重建；不能代造原回执。
   任一关键缺口保持 WAITING/BLOCKED，不以超时为由杀进程、重启或回滚。
6. 按 bootstrap 模板生成协调者和每个登记角色的启动提示词，填真实目录、批次、入口和同步映射。
   每个角色只读通用规则、索引、自身材料及相关任务；不灌入所有历史。
7. 写入后回读核对，再标 INDEX 为 SEALED，更新 latest_sealed_batch 并清空 preparing_batch。
   控制文件单一维护；中断后核对文件完整性再继续，不能凭状态字符串判成功。
8. 旧组保持暂停，快照不再修改。报告各角色表、批次、BOOTSTRAP、能力边界和唯一下一步。
   新建会话需用户授权和真实工具结果；协调者发布完成后才建立候选新组，不改变现有会话架构。

模板位于 `../assets/templates/`；只有实际需要的文件才创建。

## B. 本角色交接：由对应旧会话执行

确认项目、保存批次、角色、目标路径和回复入口来自有效指派。安全停靠后只维护自身交接材料。
按 `../assets/templates/role.template.md` 填可见历史、实际文件/Git、目标、限制、被否决方案、保护改动、接口、测试与下一步。
不可见历史写未知，不根据另一代理的总结伪造自身经历。
只写所分配角色文件和自身回执，不改 CURRENT、共享任务看板、其他角色、业务代码或密钥。
无法写目标位置时保存安全本地材料并回报，由协调者按已确认方式收集。
按 receipt 模板提供 HANDOFF_ACK，写清是否停止写入、后台作业、现场和实际送达证据。
写文件但未送达时标等待送达。完成后暂停，不能宣称协调者已收到。

## C. 更新进度：不换会话、不冻结团队

核对当前角色和项目入口，更新自己的 working/<ROLE>.md 或已有等价检查点。
记录有效结论、验证、限制、阻塞和下一步，保留必要决策原因。
向协调者回报任务变化，由协调者更新共享看板；人工方式明确需要转发。
不改封存快照，不生成批次、不切换会话、不将全组设为暂停。
