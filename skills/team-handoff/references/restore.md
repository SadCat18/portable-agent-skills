# 接管：新协调者 / 新执行角色 / 恢复调度

## A. 新协调者接管

1. 确认用户已指定本会话接管协调职责。从 BOOTSTRAP 或现有项目入口定位真实项目与批次。
   没有入口时仅检查项目根 `.agent-handoff/CURRENT.md`，已有旧目录沿用映射。
   读取 TEAM、CURRENT、SEALED 索引、协调者自身材料和任务快照；按需要查看相关角色摘要。
2. 核对全部登记角色回执、旧协调者停派单和旧角色停止相关写入。
   不齐只做预检查；用户明确选择有限重建时保留缺口并标降级，不称完整接管通过。
3. 核对自己的目录、分支/HEAD、相关 diff、未跟踪改动与交付物。
   差异未解决不继续业务；不 reset、clean 或覆盖来匹配记录。
   确认唯一候选协调者后记录接管编号，标 RESTORING 与 PAUSED。
4. 逐角色创建或绑定新会话，仅在用户授权且工具具备能力时操作。
   确保新协调者能联系新执行角色，沿用已有独立会话/子代理架构。
   缺少能力时给出 BOOTSTRAP 中逐角色完整人工启动提示词。
   resume/fork、改名或继承历史不代表干净新上下文，真实记录限制。
5. 收到每个角色真实 READY 后核对现场，对每个执行角色发独立 PING，核对相同操作/标记真实 PONG。
   只证明本次通信；人工链路与自动链路分开，不证明持续在线或自动唤醒。
6. 仅有运维职责时核对受限配置和权限，在当前授权范围内做必要只读连接/服务核实。
   配置、身份、连接、服务四项分别记录。不部署、重启、迁移或重放。
   必要运维职责不能恢复时标阻塞；用户可指定仅本地的降级范围。
7. 汇报任务、角色映射、差异、证据、权限、第一项建议动作。
   条件齐全标 READY_FOR_CONFIRMATION，派单仍 PAUSED；已有明确恢复授权则按 C 节处理，不重复询问。

## B. 新执行角色接管

核对角色、项目、批次、操作编号、工作目录和回复入口。
读取适用规则、TEAM、封存索引、自身交接与相关任务，不默认读取所有历史或运维凭据。
只读核对代码目录、分支/HEAD、改动与必要文件；回报目标、实现/验证状态、限制、保护改动、差异和第一步。
存在差异时回报阻塞，不写无条件 READY。按 receipt 模板提供真实回执，响应本次 PING。
不能直接通信则提供人工转发内容。继续暂停，直到有效协调者按用户授权派发正式任务。
不得自行升级为协调者或编辑共享控制文件。

## C. 恢复调度

有效候选协调者确认已有或新给出的用户恢复授权、接管检查仍有效、现场映射未变且没有竞争协调者。
记录授权及接管编号，将接管状态和派单状态设 ACTIVE；更新活跃任务和各角色检查点，不动封存快照。
按有效任务、依赖、范围与验收条件派单；没有任务则等待需求，不发明工作。
缺少送达/接单证据不能称已开始，结果验收后才设 VERIFIED。
恢复派单不新增部署、迁移、推送或其他操作权限。人工方式继续写清人工步骤。
